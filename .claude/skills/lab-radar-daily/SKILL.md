# 实验室雷达 · Claude 云端早报

与本地 Codex 流水线（`assets/files/06_实验室雷达/`、`assets/files/05_情报简报/`）并行的第二套保底。
规范来源：`assets/files/06_实验室雷达/实验室日报工作流.html`、`assets/files/01_提示词库/04-科技情报简报.txt`。

## 一、检索（只用 WebSearch；云端环境对 nature.com / science.org / sciencedaily.com 的 WebFetch 被网络策略拦截）

按五层信息源各至少 1 轮检索，时间窗 = 北京时间前一日 00:00 至今（最多放宽到 48h）：

| 层级 | 检索式示例 |
|---|---|
| 顶刊 | `Nature research highlights <日期>`、`Nature published <日期> wafer/quantum/cell ...`、`Science new study <日期>`、`Cell <月份> study` |
| 高校/机构 | `<日期> university researchers announce`、`中国科学院 研究团队 <日期>`、`新浪科学热点小时报 <日期>` |
| AI 实验室 | `AI news <日期> OpenAI Anthropic Google DeepMind` |
| 硬科技 | `SpaceX OR fusion OR humanoid robot news <日期>`、`quantum computing <日期>` |
| 中文媒体 | `量子位 / 机器之心 / 新华社 科学家 团队 <日期>` |

每条候选再做 1 次**定向核实检索**：确认 ①具体实验室/PI ②期刊与发表日期 ③是否同行评审（预印本必须标注）。

## 二、入选铁律（质量闸门）

1. **实验室铁律**：「今日雷达」每条必须落到具体实验室/团队/PI；落不到的只能进「前沿产业动态」。
2. **时效闸**：发表/发布日期超出 48h 窗口的，列入「剔除记录」并说明原因（例如旧论文被媒体翻炒）。
3. **事实闸**：数字必须来自检索结果原文；只有单一聚合站来源的标注【待核实】；预印本标注【预印本，未经同行评审】。禁止编造数据。
4. **口吻闸**：无营销话术、无网络流行语、零"从来/从来不是/从来不"句式；不踩一捧一。
5. **母体闸**：候选选题必须回扣「实验室」母题（现场、人物、成果、转化至少其一）。

## 三、输出结构（Markdown）

```
# 实验室雷达 · Claude 云端早报 · YYYY-MM-DD（周X）
> 生成方式 / 时间窗 / 检索轮次 / 核实说明
## 〇、今日核心结论（3 行以内）
## 一、今日雷达：顶尖实验室线索（6–8 条）
  **n.【机构 · PI/团队】标题** 正文（事实+关键数字）
  - 期刊/日期｜核实状态
  - 来源：[标题](URL)
  - 为什么值得做：（对黄师傅「实验室前线/手记/内参」的价值）
## 二、全球科技前沿 · 重大动态（4–6 条，表格：事件｜主体｜影响判断｜来源｜核实）
## 三、今日 3 个候选选题（标题方向×2 / 建议栏目 / 人文角度 / 黄金3秒钩子 / 工作量）
## 四、主编推荐（1 个 + 三条理由）
## 五、剔除记录（被闸门拦下的条目与原因）
## 六、明日待跟进
```

## 四、存盘与推送

1. 写入 `assets/files/10_Claude云端日报/YYYY-MM-DD-早报.md`（日期按北京时间）。
2. 生成 Word：`node scripts/md2docx.js assets/files/10_Claude云端日报/YYYY-MM-DD-早报.md`（输出到 `assets/files/word/`，用户 Mac 上的同步脚本会自动拷到桌面「实验室雷达」文件夹）。
3. `git add` → `git commit -m "daily: 实验室雷达 Claude 云端早报 YYYY-MM-DD"` → `git push -u origin <当前工作分支>`，网络失败按 2s/4s/8s/16s 重试。
4. 最后在会话中回复：核心结论 3 行 + 主编推荐 + 文件路径。
